# Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the public beat site from a Store view, show license tiers on the page, and import BeatStars sales exports into Sales, with BeatStars still the checkout.

**Architecture:** The existing `Catalog` service keeps owning `site_beats` and Netlify publishing; building the folder is split from deploying so it can be previewed. Page rendering and the whole importer are pure modules with no Electron or database imports, so they are unit tested directly. The renderer gets one new lazy view and one dialog, using existing styles.

**Tech Stack:** Electron 44, React 19, better-sqlite3, vitest, TypeScript. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-10-store-design.md`

## Global Constraints

- No new npm dependencies. CSV parsing is hand-written.
- No app restyle: new UI uses existing classes (`toolbar`, `shead`, `field`, `two`, `actions`, `meta-line`, `help`, `primary`, `wide`, `x`, `badge`). New CSS is limited to grid column templates for the two new tables.
- Schema changes go in ONE new function appended to `MIGRATIONS` in `src/main/db.ts`. Never edit an existing migration.
- Sale source for imported rows is exactly `'beatstars'`.
- Nothing is written to `sales` until the user presses Import; the write is one transaction.
- Adding/removing in the Store view does not publish. `Catalog.add` / `Catalog.remove` (the per-beat card) keep publishing immediately.
- Publishing in tests and manual checks uses the `STUDIO_HQ_NETLIFY_API` override, never the live Netlify API.
- `src/renderer/src/App.tsx`, `Icons.tsx` and `styles.css` have uncommitted changes that belong to the user. Stage only this plan's hunks (`git add -p`); never `git add -A`.
- Commit message style: `feat(store): …`, `fix(store): …`, ending with `Co-Authored-By: Claude <noreply@anthropic.com>`.
- Run `npm run typecheck && npm test` before every commit.

## Review Focus

1. **Money and dates as people's spreadsheets write them:** `$1,299.00`, `29.99 USD`, `(15.00)`, `10/03/2026 14:05`, `2026-10-03T14:05:00Z`. Expected: parsed correctly; an unreadable date or amount skips that row with a reason, never imports 0 or today. (Task 4)
2. **A file re-saved by Excel/Numbers:** semicolon or tab delimiter, BOM, CRLF, a trailing blank line. Expected: reads the same as the original. (Task 4)
3. **Two different beats sharing a title, or one title that exists as several versions in one group:** Expected: several groups → unmatched, user picks; one group → the newest file in it. (Task 4)
4. **License names and perks containing `<`, `"`, `&` or `</script>`:** Expected: shown as text on the public page, page still works. (Task 2)
5. **Same order imported again after the user changed the column mapping or after the export gained rows:** Expected: old orders are "already imported", only new ones are written. (Task 5)

### Task 4: BeatStars importer (pure)

**Files:**
- Create: `src/main/beatstars-import.ts`, `src/main/beatstars-import.test.ts`
- Modify: `src/shared/types.ts`

**Interfaces:**
- Produces (in `types.ts`):
  - `type ImportField = 'orderId' | 'date' | 'title' | 'license' | 'buyer' | 'email' | 'gross' | 'fee' | 'net'`
  - `type ColumnMap = Partial<Record<ImportField, number>>` (header index)
  - `type ImportRowStatus = 'new' | 'duplicate' | 'unmatched' | 'skipped'`
  - `interface ImportRow { line: number; externalId: string; title: string; license: string; buyer: string; email: string; price: number; fee: number; soldAt: number | null; beatId: number | null; licenseId: number | null; exclusive: boolean; status: ImportRowStatus; reason: string }`
  - `interface ImportRead { headers: string[]; columns: ColumnMap; missing: ImportField[]; rows: ImportRow[] }`
- Produces (in `beatstars-import.ts`, no Electron/db imports):
  - `parseCsv(text: string): string[][]`
  - `detectColumns(headers: string[], saved?: ColumnMap): { columns: ColumnMap; missing: ImportField[] }`
  - `parseMoney(s: string): number | null`, `parseDate(s: string): number | null`
  - `interface BeatRef { id: number; groupId: number; title: string; siteTitle: string | null; mtime: number }`
  - `planImport(input: { table: string[][]; columns: ColumnMap; beats: BeatRef[]; licenses: License[]; existingIds: Set<string>; choices?: Record<number, number | null>; exclusiveLocks: Map<number /*groupId*/, number /*soldAt*/> }): ImportRow[]`

Decisions:
- Required fields: `orderId`, `date`, `title`, `gross`. `missing` lists the required ones not mapped.
- `KNOWN_HEADERS: Record<ImportField, string[]>` (compared after lowercasing and stripping non-alphanumerics): orderId `orderid, ordernumber, order, transactionid, invoice`; date `date, orderdate, purchasedate, createdat, soldat`; title `title, tracktitle, trackname, track, beat, item, itemname, productname`; license `license, licensetype, licensename`; buyer `buyer, buyername, customer, customername, name`; email `email, buyeremail, customeremail`; gross `gross, amount, price, total, grossamount, saleprice`; fee `fee, fees, servicefee, platformfee, commission`; net `net, netamount, earnings, payout`. A `saved` map wins where its index is in range.
- `parseCsv`: delimiter is whichever of `,` `;` `\t` occurs most in the first line outside quotes; handles BOM, CRLF, `""` escapes, newlines inside quotes; fully empty lines dropped.
- `parseMoney`: strips currency symbols, letters, spaces and thousands commas; `(15.00)` and `-15` are negative; anything else → `null`.
- `parseDate`: ISO (`YYYY-MM-DD`, optional time, optional `Z`/offset) and US `M/D/YYYY` with optional `H:MM[:SS]` and `AM/PM`; date-only is local noon; anything else → `null`.
- `externalId`: the order id; when an order id appears on more than one row, `<orderId>:<n>` with n counted from 1 in file order.
- `fee`: the fee column; else `gross − net` clamped to `[0, gross]`; else 0.
- Title matching, case-insensitive, first rule that finds any candidate wins: exact `siteTitle`; exact `title`; `siteTitle()`-normalised (import it from `./catalog-title`, see below). Candidates in one group → the highest `mtime` beat; several groups or none → `unmatched`. `choices[line]` overrides: a beat id matches it, `null` makes it `skipped` (reason `Skipped by you`).
- `siteTitle` moves from `catalog.ts` to a new electron-free `src/main/catalog-title.ts`; `catalog.ts` re-exports it.
- License: `licenseId` is the tier whose name equals the file's license (case-insensitive); `exclusive` is that tier's flag, else `/exclusive/i` on the name. Empty license name → `Lease`.
- Empty buyer → `BeatStars customer`.
- Status order: unreadable date or amount → `skipped` (`Couldn't read the date` / `Couldn't read the amount`); amount ≤ 0 → `skipped` (`Refund or zero amount`); `externalId` in `existingIds` → `duplicate`; no beat → `unmatched`; group has an exclusive lock at or before `soldAt`, or the row is exclusive and the group has any lock → `skipped` (`Already sold exclusively`); two exclusive rows for one group in the same file → the later is `skipped` likewise; else `new`.

- [ ] **Step 1: Failing tests**, one `test` per bullet above, plus Review Focus 1–3 as named tests: `'reads money as spreadsheets write it'` (`$1,299.00`→1299, `29.99 USD`→29.99, `(15.00)`→-15, `abc`→null), `'reads ISO and US dates'` (`10/03/2026 2:05 PM` → Oct 3 2026 14:05 local; `2026-10-03T14:05:00Z` → that instant; `03.10.26` → null), `'an Excel re-save reads the same'` (same rows as `;`+BOM+CRLF+trailing blank line → deep-equal table), `'same title in two groups is unmatched; several versions in one group picks the newest'`.
